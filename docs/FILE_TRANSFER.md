# Android ↔ Windows 文件互传

## 使用

两端使用最新开发构建，原有二维码配对可继续使用。文件支持双向发送。手机底部进入“文件”，点“选择文件 · 自动发送”，系统文件选择器支持多选任意类型。文件逐个发送，列表显示大小、已传字节和状态，支持取消、失败重试及清理完成记录。

电脑切换到“文件”，将文件拖入发送区，或先在资源管理器复制文件后按 Ctrl+V/点击“粘贴文件”，即可自动发送。也可以点击“选择文件发送到手机”多选。离线时保留队列；支持取消待发任务。也可打开已完成文件、定位文件或更改接收目录。默认目录为 Windows 的下载目录下 `MobileVision/年-月-日`。同名文件生成 `名称 (2).扩展名`，依次递增，不覆盖已有内容。文件不会自动打开、执行或粘贴。

电脑发送时先复制到 App 暂存空间并计算 SHA-256，后续修改原文件不影响队列。手机在前台接收、显示进度，校验后自动保存到系统“下载/MobileVision”。文件通过 MediaStore 发布，同名不覆盖，支持点击打开。清理记录不删除已接收的公共下载文件。写入期间先保持不可见的 pending 状态，发布成功后才确认电脑并清理暂存。完成确认丢失时按原任务确认，不重复保存。手机接收阶段需留出暂存和最终保存所需的空间。

手机原文件不修改。导入时复制到 App 私有空间，避免系统提供方失效或原文件变化；上传成功或取消获电脑确认后删除暂存副本。清理记录不删除电脑文件。准备大文件时手机需要相应剩余空间。卸载 App 会删除本地待传文件。

保持 App 在前台；切后台暂停后续分块，当前请求可能继续完成。连接恢复或重新打开 App 后按电脑确认的位置继续。取消离线任务时显示“等待电脑确认取消”，恢复连接后清理电脑未完成文件；电脑已经完成的文件保留。换到其他电脑时原电脑的任务会等待原连接。

## 协议与持久化

复用照片协议的 HTTPS、电脑证书指纹与 Bearer 配对凭据，不新增明文端口。文件上限 2 GiB，每块最大 4 MiB，允许空文件。使用稳定 UUID、原始文件名、字节数和 SHA-256 初始化任务。

| 请求 | 功能 |
| --- | --- |
| `POST /api/v1/files/{id}` | JSON `name/bytes/sha256`；创建或返回原任务 |
| `GET /api/v1/files/{id}` | 查询电脑确认的进度 |
| `PUT /api/v1/files/{id}/chunk` | 二进制；Content-Length 与 X-File-Offset 必须匹配 |
| `POST /api/v1/files/{id}/complete` | 校验全部内容后保存，重复调用不重复保存 |
| `DELETE /api/v1/files/{id}` | 清除未完成任务；已完成返回 FILE_ALREADY_COMPLETE |

进度响应为 `id/offset/bytes/state/receivedAt`，状态为 pending 或 ready。每块写盘并同步后才更新 SQLite 日志。断电后截掉尚未写入日志的尾部。客户端每次先重新提交元数据以恢复服务端真实进度，因此响应丢失不会使文件重复追加。

完成前校验大小及完整 SHA-256，校验失败将电脑进度重置为 0，手机标记需要处理，用户可重试或重新选原文件。最终保存采用硬链接或排他复制，不覆盖目标文件。未完成内容放在日期目录的 `.mobilevision-part` 子目录，接收成功后清理对应暂存文件。

保存目录变更影响之后创建的任务，正在续传的任务继续使用原目录。列表显示最近 500 个电脑任务；旧文件继续留在磁盘。暂不提供后台常驻传输或文件多选删除。发送区支持多选磁盘文件，每次最多 200 个；文件夹暂不支持。文字剪贴板会提示到文本页发送，图片或其他虚拟剪贴板内容不会作为磁盘文件发送。拖放仅在文件发送区生效，Ctrl+V 仅在文件页处理，不影响文本页正常粘贴。

## 电脑到手机协议

| 请求 | 功能 |
| --- | --- |
| `GET /api/v1/downloads` | 当前手机最早的待发文件，返回 id/name/bytes/sha256 |
| `GET /api/v1/downloads/{id}/chunk?offset={bytes}` | 返回 id/offset/data，data 为最多 4 MiB 二进制的 Base64 |
| `POST /api/v1/downloads/{id}/ack` | JSON offset/complete/canceled/sha256，确认进度或完成/取消 |

手机每块写盘同步、提交本地进度后才确认电脑。最终确认必须报告全部字节与正确 SHA-256。电脑保留已完成任务的确认记录，并清理发送副本。更换手机不会把旧设备的待发文件发给新设备。电脑或手机取消正在传输的任务时，已保存完成的手机文件保留。

拖放通过预加载脚本使用 [Electron webUtils](https://www.electronjs.org/docs/latest/api/web-utils) 解析原生 File 路径，不向页面开放任意磁盘读取接口。资源管理器文件粘贴使用隐藏的 Windows STA 剪贴板辅助进程，不拼接文件名到命令代码中。

## 验证

- Windows：`npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run smoke`。
- Android：`:app:assembleDebug`、`:app:assembleDebugAndroidTest`、`:app:testDebugUnitTest`。
- 可选连接设备测试：安装应用和测试 APK 后，在 windows 目录设置 `MOBILEVISION_FILE_TEST_DEVICE` 为 adb 序列号，运行 `npx.cmd tsx --test tests/files-device.test.ts`。仅使用独立接收服务、临时目录与合成文件，测试后移除对应 adb reverse 映射。不会读取真实文件或改变正式配对记录。

测试覆盖服务端重启续传、确认丢失、重复完成、同名保护、取消、校验失败、空文件和身份认证，以及 Android 双向文件队列恢复、手机下载目录发布、同名保护和跨端二进制一致性。设备测试通过 adb 通道验证两端实现，不能代替真实 Wi-Fi、系统文件选择器和 2 GiB 文件的现场验收。
