# 双向文本消息（开发版）

两端使用最新开发构建，通过原配对连接收发文本。手机底部进入“文本”，电脑点击“文本”标签。输入支持多行，保留空格、缩进、换行和 Unicode；每条最多 64 KiB，按 UTF-8 字节计算。

手机有“发送”和“发送并复制到电脑”。后者在电脑首次收到时写入剪贴板，不自动粘贴。电脑 Enter 换行、Ctrl+Enter 发送。消息可选中文字、复制或主动打开 http/https 链接，不自动打开或执行内容。两端草稿在本地保存，切换页面或重开后保留。

## 状态与离线

手机发送任务保存在 SQLite，网络暂时失败后自动重试；永久错误显示“发送失败”，用户可以重试。电脑发送任务同样持久保存，显示“等待手机接收”，在手机打开 App 并连接后送达。手机前台定时取一条电脑待送消息，先存盘再确认；没有后台推送、已读回执或自动插入焦点输入框。

重复发送和确认通过消息 UUID 去重。“已送达”表示另一端保存成功，不表示对方已阅读。发送并复制只触发一次，不会因网络重试覆盖用户后来复制的其他内容；电脑进程在保存记录与操作剪贴板之间崩溃时可能未完成自动复制，仍可点击消息的“复制”。

查看旧消息时提示“有新消息”，点击后回到最新记录；在底部时自动跟随。换电脑后手机只显示当前电脑的消息，原电脑的队列仍保留，连接原电脑后继续发送。电脑旧配对设备的待送任务不会发给新设备。

“清理已送达”只清理当前设备的已送达内容，保留待发送任务。内部保留消息 ID 去重记录，避免确认丢失时清理过的消息再次出现。两端最多显示最近 500 条可见记录，较早待传任务仍由数据库处理。手机清理作用于全部电脑的已送达记录。

## 接口

复用 HTTPS、证书指纹与 Bearer 凭据。

| 请求 | 用途 |
| --- | --- |
| `POST /api/v1/messages/{uuid}` | 手机发送 JSON `text`、`copy`（布尔值）；返回 id/state |
| `GET /api/v1/messages` | 获取当前配对手机最早的一条电脑待发消息 |
| `POST /api/v1/messages/{uuid}/ack` | 手机存盘后确认，可重复调用 |

文本内容不作为 HTML 渲染。长度按解析后的 UTF-8 文本计，JSON 请求另有限额，防止转义膨胀造成大请求。诊断日志不记录文本内容。

## 验证与范围

Windows 测试覆盖认证、Unicode/换行、64 KiB 边界、重复请求、复制一次、重启保持待发队列和清理后去重；窗口测试验证收发、剪贴板及 Ctrl+Enter。独立手机测试使用临时数据库与合成文本，不修改正常配对或消息历史。

设备测试：安装最新应用和仪器测试 APK，在 windows 目录设置 `MOBILEVISION_TEXT_TEST_DEVICE` 为 adb 序列号，运行 `npx.cmd tsx --test tests/messages-device.test.ts`。测试使用 adb reverse，不能代替真实 Wi-Fi 断连和后台恢复的现场验收。
